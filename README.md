# Lumen Remote

Мобильное приложение для удалённого доступа к экрану телефона: одно Android-устройство
транслирует экран, другое показывает его в реальном времени и управляет им касаниями,
свайпами, системными клавишами и вводом текста.

Интерфейс — тёмная тема «midnight aurora» на Material 3: градиентные карточки,
анимированный радар ожидания, стеклянные панели, моноширинные коды подключения,
собственная нижняя навигация с подсветкой активной вкладки.

## Возможности

**Приём подключения (Android)**

- 9-значный код устройства и 4-значный PIN: генерируются через `SecureRandom`
  и сохраняются между запусками.
- Захват экрана через `MediaProjection` в foreground-сервисе с типом
  `mediaProjection`; JPEG-кадры до 24 к/с, качество 30–90 %.
- Удалённое управление через `AccessibilityService`: тап, свайп, «Назад», «Домой»,
  «Недавние», «Уведомления», ввод текста в активное поле.
- Два транспорта: **локальная сеть** (прямой TCP, работает без интернета) и
  **интернет** (WebSocket через relay-сервер).
- Постоянное уведомление о трансляции с кнопкой «Остановить».
- Чек-лист разрешений прямо на экране: захват экрана, управление, уведомления.

**Удалённое подключение**

- Ввод кода (интернет) или IP-адреса (локальная сеть) + PIN.
- Просмотр экрана с сохранением пропорций, индикаторы задержки (мс) и частоты кадров.
- Переключение «Просмотр / Управление», касания и свайпы с визуальным откликом.
- Экранная клавиатура для ввода текста на удалённом устройстве.
- Снимок экрана партнёра в галерею (`Pictures/Lumen Remote`).
- Автообнаружение принимающих устройств в локальной сети (UDP-broadcast).
- История подключений, повторное подключение одним нажатием (долгое нажатие — удалить).

**iOS-устройства**

- **iPhone как клиент**: веб-клиент в Safari (`server/web`) — просмотр экрана Android
  и управление касаниями, клавиатурой, ссылками и буфером обмена без App Store.
- **iPhone как источник экрана**: ReplayKit broadcast-расширение отправляет экран
  iPhone на relay-сервер, Android-устройство его показывает.
- **Ограниченное управление iOS**: ссылки (`open_url`), буфер обмена (`clipboard`),
  просмотр. Инъекция касаний в iOS недоступна сторонним приложениям.
- Референс-приложение для iOS на SwiftUI — в каталоге `ios/`.

## Как это работает

```
Телефон A (приём)                              Телефон B (просмотр)
┌───────────────────────────┐                  ┌───────────────────────────┐
│ MediaProjection           │  JPEG-кадры ───▶ │ RemoteScreenView          │
│   → ScreenShareService    │                  │   декодирование Bitmap    │
│ AccessibilityService      │ ◀── JSON ─────── │ касания → нормализованные │
│   жесты, клавиши, текст   │  tap/swipe/key   │ координаты 0..1           │
└───────────────────────────┘                  └───────────────────────────┘
            ▲                                                ▲
            └──── TCP :8731 (LAN) или WebSocket relay (интернет) ────┘
```

- Управляющие сообщения — JSON, кадры — бинарный JPEG.
- В локальной сети используется TCP с кадровкой `[тип 1 Б][длина 4 Б][payload]`.
- Через интернет обе стороны подключаются к relay-серверу по коду и PIN; сервер
  сопрягает пару и пересылает сообщения, не сохраняя содержимое сеанса.
- Автообнаружение: принимающее устройство рассылает UDP-broadcast на порт `8890`,
  порт сеанса — `8731`.
- `MediaProjection` отдаёт кадр только при изменении изображения (frame-on-damage):
  на статичном экране трафик отсутствует, что экономит батарею и сеть.

## Быстрый старт

Требования: Android 7.0+ (API 24), JDK 17+, Android SDK 37.

```bash
./gradlew assembleDebug        # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug         # установка на подключённое устройство
```

Порядок работы:

1. **Принимающее устройство**: «Главная» → «Принимать подключения» → «Начать
   трансляцию» → подтвердить системный захват экрана.
2. Для управления включите службу «Lumen Remote — управление» в
   *Настройки Android → Специальные возможности* (или по строке «Удалённое
   управление» на экране приёма).
3. **Клиент**: вкладка «Устройства» — устройство появится в блоке «Рядом с вами»
   автоматически; либо введите IP-адрес и PIN на главной странице.
4. Через интернет — см. [Relay-сервер](#relay-сервер): введите 9-значный код и PIN.

## Режимы подключения

### Локальная сеть (по умолчанию)

- Прямое TCP-соединение, интернет не нужен.
- Принимающая сторона слушает порт `8731`, клиент вводит её IP-адрес.
- Устройства находят друг друга по UDP-broadcast на порт `8890`
  (вкладка «Устройства», блок «Рядом с вами»).
- Требуется, чтобы Wi-Fi сеть разрешала обмен между клиентами (без «изоляции
  клиентов»), а брандмауэр не блокировал порты `8731/8890`.

### Через интернет (relay)

- Обе стороны подключаются к relay-серверу по WebSocket; сопряжение — по
  9-значному коду и PIN.
- Работает из любой сети, в том числе за NAT.
- Адрес сервера задаётся в *Настройках → Relay-сервер*, формат `ws://host:port/ws`
  или `wss://host/ws` (TLS).

## Relay-сервер

Каталог `server/` содержит минимальный сервер сопряжения на Node.js (`ws`).

```bash
cd server
npm install
npm start                 # ws://0.0.0.0:8080/ws
PORT=9000 npm start       # другой порт
```

Проверка: `curl http://localhost:8080/health` → `{"status":"ok","rooms":N}`.
Веб-клиент для iPhone/iPad открывается по адресу `http://<сервер>:8080/`
(файлы из `server/web`): код, PIN и управление — прямо в Safari.
Совместимость: Safari 13+, Chrome 51+ (есть fallback на `touch`-события),
Firefox. Быстрый старт из ссылки: `/?relay=wss://host/ws#auto:КОД:PIN` —
фрагмент `#auto` не отправляется на сервер, код и PIN остаются у клиента.

Что делает сервер:

- принимает `{"t":"host","code","pin"}` (создаёт комнату) или
  `{"t":"viewer","code","pin"}` (входит в комнату);
- проверяет PIN, отклоняет второго зрителя (`busy`) и несуществующие комнаты
  (`not_found`);
- после сопряжения прозрачно пересылает текстовые и бинарные сообщения между
  участниками комнаты;
- уведомляет вторую сторону событиями `peer_joined` / `peer_left`;
- не хранит кадры и не декодирует содержимое; комнаты живут до 12 часов,
  «мёртвые» сокеты отсекаются ping/pong каждые 30 секунд.

Для продакшена: поставьте сервер за TLS-прокси (nginx/Caddy) и используйте
`wss://`, ограничьте `maxPayload`, включите журналирование и rate-limit.

## Протокол сеанса

Текстовые сообщения — JSON, поле `t` задаёт тип. Кадры передаются отдельно:
в LAN — кадры протокола, в WebSocket — бинарные сообщения.

| Тип | Направление | Поля | Назначение |
|---|---|---|---|
| `auth` | зритель → хост | `pin` | проверка PIN |
| `auth_ok` | хост → зритель | `name`, `platform`, `model`, `w`, `h`, `control`, `pin` | доступ разрешён + параметры экрана |
| `auth_fail` | хост → зритель | — | неверный PIN |
| `hello` | оба | `name`, `platform`, `model`, `w`, `h`, `control`, `pin` | приветствие и возможности |
| `tap` | зритель → хост | `x`, `y` (0..1) | касание |
| `swipe` | зритель → хост | `x1`, `y1`, `x2`, `y2`, `ms` | свайп |
| `key` | зритель → хост | `k` = `back`/`home`/`recents`/`notifications` | системная клавиша |
| `text` | зритель → хост | `s` | ввод текста в активное поле |
| `cmd` | зритель → хост | `action` = `open_url` / `clipboard`, `value` | команды, работающие и на iOS (без инъекции жестов) |
| `quality` | зритель → хост | `fps`, `q` | запрос частоты кадров и качества JPEG |
| `ping` / `pong` | оба | `ts` | измерение задержки, контроль соединения |
| `bye` | оба | — | корректное завершение |
| `peer_joined` / `peer_left` | relay → клиент | — | события комнаты |

Транспорт LAN:

```
[1 байт: 1=JSON, 2=JPEG][4 байта: длина payload, big-endian][payload]
```

Транспорт relay: текстовые WebSocket-сообщения (JSON как есть) и бинарные
WebSocket-сообщения (JPEG без обёртки); первое сообщение — `host`/`viewer`-join.

## Разрешения и системные службы

| Разрешение / служба | Зачем |
|---|---|
| `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`, `CHANGE_WIFI_MULTICAST_STATE` | сеть и UDP-обнаружение |
| `POST_NOTIFICATIONS` (33+) | уведомление о трансляции |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PROJECTION` | захват экрана в фоне |
| `MediaProjection` (системный диалог) | согласие пользователя на трансляцию |
| `AccessibilityService` (`RemoteControlService`) | жесты, клавиши, ввод текста |
| `WRITE_EXTERNAL_STORAGE` (≤ API 28) | снимок экрана в галерею |

Служба доступности используется только во время сеанса и может быть отключена в
любой момент; захват экрана всегда требует явного подтверждения пользователя.

## Безопасность

### Что защищает приложение

| Механизм | Где | Поведение |
|---|---|---|
| Подтверждение подключения | `HostSession`, `ConnectionApproval` | диалог в приложении и уведомление с кнопками «Разрешить»/«Отклонить»; без ответа через 60 с подключение отклоняется. Отключается в настройках |
| Защита от перебора PIN | `AuthGuard` | после 5/8/12 неверных попыток — блокировка 30 с / 5 мин / 1 ч по адресу партнёра |
| Шифрование LAN | `LanCrypto`, `SecureHandshake` | одноразовый ECDH (P-256) + подтверждение по PIN + AES-256-GCM на каждый кадр; при старом партнёре — обычный канал |
| Длина PIN | `Ids.PIN_LENGTH` | 6 цифр; старый 4-значный PIN хоста заменяется 6-значным при обновлении, ввод зрителя принимает 4-6 цифр |
| Лимит подключений | `LanServer` | не более 4 одновременных входящих соединений |
| Минимум до аутентификации | `HostSession.hostHello(anonymous)` | имя устройства, модель и разрешение экрана не раскрываются до ввода PIN |
| Приватность в сети | `Prefs.discoverable` | UDP-обнаружение можно выключить — устройство не будет видно в списке |
| Ограничения команд | `HostSession.canControl` | управление требует авторизованного сеанса и включённой службы доступности; `open_url` — только `http(s)`; буфер обмена — по настройке |
| Relay | `server/relay.js` | allowlist Origin (fail-closed, same-origin по умолчанию), лимит попыток входа, лимит комнат и размера сообщений, `X-Forwarded-For` только от локального доверенного прокси, заголовки CSP/nosniff/frame-options, маскирование кода комнаты в логах |

### Защита канала

- **Соединение с новым клиентом шифруется.** PIN и кадры не идут открытым текстом: одноразовый
  ECDH (P-256) даёт общий секрет, HKDF-SHA256 выводит ключи, подтверждение сторон считается через
  HMAC с примесью PIN, а каждый кадр шифруется AES-256-GCM. С версиями до 1.0.10 соединение
  остаётся незашифрованным — режим виден в состоянии сеанса.
- **Ограничение схемы:** это ECDH с подтверждением по PIN, а не полноценный PAKE. При активной
  MITM-атаке на этапе рукопожатия возможен офлайн-перебор 6-значного PIN; подмена содержимого без
  PIN невозможна.

### Известные ограничения

- Relay видит трафик в расшифрованном виде (TLS терминируется на сервере) — это часть
  доверия к оператору relay.
- PIN хранится в обычных `SharedPreferences`; резервное копирование отключено (`allowBackup=false`).


### Ручные харнессы для сквозной проверки (`tools/`)

Для проверки без второго телефона в репозитории есть Python-утилиты
(нужен Python 3.10+; для relay — пакет `websockets`).

| Скрипт | Роль |
|---|---|
| `lumen_wire.py` | общие примитивы протокола: кадровка, чтение/запись, хелперы `hello`/`auth` |
| `fake_host.py` | «принимающее» устройство в LAN: auth, hello, поток кадров |
| `fake_viewer.py` | «просматривающее» устройство: auth, приём кадров, tap и `key=home` |
| `dev_relay.py` | локальный relay-сервер, аналог `server/relay.js` |
| `fake_relay_host.py` | «принимающее» устройство через relay (`--platform iOS` эмулирует iPhone) |
| `web_server.py` | раздача `server/web` без кэширования (отладка веб-клиента) |
| `inspect_web.py` | инспектор веб-клиента через Chrome DevTools: состояние формы, ошибки JS, касания |
| `relay_smoke.py` | дымовой тест relay: зритель получает `ready` |

Примеры:

```bash
# приложение-клиент против тестового хоста в LAN
python tools/fake_host.py --image screenshots/test.jpg --name=FakePixel

# тестовый клиент против приложения-хоста (после adb forward tcp:8731 tcp:8731)
adb forward tcp:8731 tcp:8731
python tools/fake_viewer.py --pin 7307 --out frame.jpg

# режим relay
python tools/dev_relay.py 8080
python tools/fake_relay_host.py --code 284913706 --pin 4821
```

Проверено на эмуляторе (API 36):

- LAN: подключение, PIN, приём кадров, отправка `tap`/`swipe` — координаты
  нормализуются корректно с учётом letterbox;
- приём: `MediaProjection` + foreground-сервис, PIN, поток кадров,
  удалённое нажатие `key=home` реально уводит устройство на рабочий стол;
- relay: сопряжение по коду, обмен кадрами и командами через WebSocket;
- веб-клиент (сценарий «iPhone в Safari»): автоподключение по ссылке
  `?relay=…#auto:КОД:PIN`, `auth`, `hello` с `platform: iOS`, приём кадров
  (canvas 1080×2400), `ping`/`pong`. Проверено в Chrome 51 (эмулятор Android 7);
  веб-клиент совместим с Safari 13+ и современными Chrome/Firefox;
- история подключений и сохранение кода/PIN между запусками.

```bash
cd server
cp .env.example .env      # RELAY_DOMAIN, ALLOWED_ORIGINS, лимиты
docker compose up -d --build
curl -fsS https://<домен>/health
```

В комплекте: Dockerfile (non-root), docker-compose с Caddy (автоматический TLS),
systemd-юнит, структурированные логи, `/health` и `/ready`, лимиты и белый список Origin.

## Качество кода и соглашения

### Kotlin / Android

- Пакеты по слоям: `core`, `net`, `host`, `control`, `ui`, `util`.
- Публичные классы и функции документированы KDoc; комментарии — по-русски.
- Никаких «магических» строк протокола в UI и сессии: ключи и разбор сосредоточены
  в `Proto` (`parseTap`, `parseSwipe`, `parseQuality`, `parseHello`).
- Транспорты не дублируют инфраструктуру: очередь сообщений, события и флаг
  соединения вынесены в `BasePeerChannel`; `LanChannel` и `RelayChannel`
  реализуют только свой транспорт.
- Сетевой ввод-вывод никогда не выполняется в главном потоке: запись в сокет
  идёт через очередь и фоновый корутин-цикл.
- Единые константы: `Ids.CODE_LENGTH`, `Ids.PIN_LENGTH`, `Proto.MIN_FPS/MAX_FPS`,
  `NetUtils.DEFAULT_PORT/DISCOVERY_PORT`.
- Повторяющиеся элементы интерфейса вынесены: `InputViews` (поля для диалогов),
  `PinPrompt`, `DeviceUi.fromRecord/fromNearby` (маппинг моделей в UI-элементы).
- Стили и размеры — в `res/values` (`styles.xml`, `dimens.xml`, `colors.xml`).

### Python (tools/)

- Стиль — PEP 8, контроль: `python -m pycodestyle tools` (0 замечаний),
  конфигурация в `setup.cfg` (`max-line-length = 79`).
- Каждый модуль и функция имеют docstring; у функций есть аннотации типов.
- Общие примитивы протокола вынесены в `tools/lumen_wire.py` (DRY): кадровка,
  чтение сообщений, подключение, сборка `hello`/`auth`.
- Аргументы командной строки разбираются через `argparse`.

### JavaScript (server/)

- CommonJS, единый стиль отступов, протокол задокументирован в шапке файла,
  логика комнат отделена от обработки сокетов.

## Безопасность и ограничения

- PIN обязателен по умолчанию; неверный PIN закрывает соединение. Партнёра можно
  отключить в любой момент, трансляция всегда видна в уведомлении.
- Релизная сборка запрещает cleartext-трафик: relay работает только по `wss://`,
  резервные копии приложения отключены (`allowBackup=false`).
- Трафик не шифруется на уровне приложения — для интернета используйте только `wss://`;
  в LAN-режиме шифрования нет (прямой TCP в доверенной сети).
- Защищённые окна (`FLAG_SECURE`) не попадают в трансляцию — ограничение Android.
- Одновременно обслуживается один зритель; второй получает отказ (`busy`).
- Нет передачи файлов и звука; управление — только жесты, клавиши и текст.
- **iOS**: поддерживаются три сценария — веб-клиент в Safari (просмотр и управление
  Android), нативное приложение `ios/` и трансляция экрана iPhone через ReplayKit.
  Управлять самим iOS-устройством касаниями нельзя: платформа не даёт API инъекции
  событий. Доступны `open_url` и `clipboard`.

## Аудит причин чёрного экрана

Проверено по коду приложения (v1.0.4):

| Причина | Что в приложении | Может ли дать чёрный экран |
|---|---|---|
| `FLAG_SECURE` | флаг нигде не выставляется (ни Activity, ни тема) | только для защищённых окон у партнёра; собственный экран не защищён |
| DRM (Widevine/HDCP) | декодирования DRM нет | да, но только для DRM-окон (кино-сервисы); весь экран не чернеет |
| Foreground Service | тип `mediaProjection`, `startForeground()` вызывается до `getMediaProjection()` | нет; на EMUI без разрешения на уведомления сервис мог останавливаться — закрыто диалогом |
| SurfaceView / TextureView | не используются: `ImageReader` → `Bitmap` → `ImageView` | нет |
| WebView | в приложении нет | нет |
| Оверлеи (`SYSTEM_ALERT_WINDOW`) | не запрашиваются, оверлеев нет | нет |
| Кодеки и HW-ускорение | `MediaCodec` не используется, JPEG — программный | только в запасной ветке HardwareBuffer: при сбое копии кадр пропускается (видно в логах) |

Остающийся подозреваемый — поведение `MediaProjection` конкретной прошивки (EMUI/HarmonyOS):
поэтому захват идёт в нативном размере, есть резервная стратегия через `ImageFormat.PRIVATE`,
watchdog первого кадра и повтор последнего JPEG.

## Диагностика проблем

| Симптом | Причина и решение |
|---|---|
| «Устройство недоступно» в LAN | Разные сети, включена изоляция клиентов, брандмауэр блокирует `8731`. Проверьте `ping <ip>` и запустите хост заново. |
| Устройство не появилось в «Рядом с вами» | UDP-broadcast блокируется сетью; введите IP-адрес вручную. |
| «Неверный PIN-код» | PIN менялся на принимающей стороне — посмотрите актуальный на экране приёма. |
| «Relay-сервер недоступен» | Проверьте адрес в настройках (`ws://host:8080/ws`), доступность `curl http://host:8080/health`, схему `wss://`. |
| Чёрный экран вместо изображения | Партнёр не подтвердил захват экрана, контент защищён `FLAG_SECURE` или экран хоста выключен. На экране приёма есть живая диагностика: кадры, к/с и размер кадра |
| **Huawei / HarmonyOS: чёрный экран** | Не блокируйте экран хоста (приложение удерживает его включённым, но ручная блокировка/сон всё равно останавливают кадры); разрешите уведомления — без них система может остановить трансляцию. Приложение само пересоздаёт поверхность захвата и, если кадры не идут, пробует `ImageFormat.PRIVATE`/HardwareBuffer |
| **Huawei / HarmonyOS: касания не работают** | Включите службу «Lumen Remote — управление» заново (EMUI/HarmonyOS выгружает службы доступности); на экране приёма появится предупреждение «Служба включена, но не подключена». Если в логах `LumenControl: dispatchGesture отклонён` — система блокирует жесты |
| Касания не работают | На принимающем устройстве не включена служба «Lumen Remote — управление». |
| Кадры идут рывками | Снизьте качество/частоту кадров в настройках или приблизьте устройства к роутеру. |
| Эмулятор не видит хост-машину | Используйте адрес `10.0.2.2` вместо `127.0.0.1`. |
